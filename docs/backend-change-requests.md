# 백엔드 변경 요청

프론트엔드에서 확인한 게임 진행 및 로비 실시간성 문제를 해결하기 위한 백엔드 변경 요청이다.

## 1. 최후 변론 후보자의 발언 허용

### 현재 문제

프론트엔드는 `FINAL_DEFENSE` 단계에서 단독 최다 득표 후보자에게 발언 입력을 제공한다. 현재 서버 규칙은 `/pub/rooms/{roomCode}/speak`를 `SPEECH`의 현재 차례 생존자만 허용하므로, 후보자의 최후 변론 발언이 거부된다.

### 요청 계약

- `FINAL_DEFENSE` 진행 중에는 최후 변론 후보자 한 명의 `/pub/rooms/{roomCode}/speak`를 허용한다.
- 허용된 발언은 기존과 같은 `PLAYER_SPOKEN` 이벤트로 해당 방 구독자에게 브로드캐스트한다.
- 이 발언은 일반 라운드의 발언 횟수, 현재 턴, 다음 단계 전이에 영향을 주지 않는다.
- 후보자가 아닌 플레이어, 탈락자, 마감 시각 이후의 요청은 거부한다.

### 완료 조건

후보자가 10초 안에 보낸 발언이 모든 참가자의 채팅 로그에 표시되고, 10초 뒤 `FINAL_VOTE_STARTED`가 정상 발행된다.

## 2. 공개방 목록의 실시간 구독

### 현재 문제

STOMP `CONNECT`는 `roomCode`, `playerId`, `playerSecret`을 모두 요구한다. 따라서 방에 입장하지 않은 로비 사용자는 `/sub/rooms`를 구독할 수 없고, 프론트엔드는 1초 REST 폴링으로만 목록을 갱신한다.

### 요청 계약

- 공개방 목록 전용 익명 구독을 허용하거나, 방 코드 없이 발급·검증 가능한 별도 로비 세션 인증을 제공한다.
- 해당 구독자는 공개방의 생성, 수정, 삭제 시 즉시 `/sub/rooms` 이벤트를 받는다.
- 이벤트의 방 요약 데이터는 REST 목록 응답과 같은 필드를 제공한다.
- 비공개방의 생성·수정·삭제 정보는 이 구독에 포함하지 않는다.

### 완료 조건

A가 공개방을 생성·입장·퇴장·시작하면 B와 C의 로비 목록이 REST 폴링을 기다리지 않고 해당 이벤트로 즉시 갱신된다.
