# 수동 검증 체크리스트 (Manual Test Checklist)

본 체크리스트는 최근 프론트엔드 변경 사항(투표 결과 복원 및 다음 라운드 연동) 및 향후 검증해야 할 알려진 이슈들을 정리한 문서입니다.

---

## 1. 최근 수정 사항 수동 검증 절차

### [ ] 시나리오 1: VOTE_RESULT 새로고침 복원 검증
1. 3인 이상의 플레이어로 게임을 시작합니다.
2. 발언 단계를 완료한 후 투표 단계로 진입합니다.
3. 모든 플레이어가 투표를 정상적으로 완료합니다.
4. 화면에 **투표 결과 화면(탈락자 공개)**이 정상 노출되는지 확인합니다.
5. 이 상태에서 브라우저 **새로고침(F5)**을 실행합니다.
6. **검증 기준**: 새로고침 후에도 이전의 투표 결과 정보(최다 득표자 닉네임, 라이어 여부 등)가 깨지지 않고 그대로 노출되는지 확인합니다.

### [ ] 시나리오 2: 다음 라운드 진입 연동 검증
1. 투표 결과 화면에서 한 명 이상의 플레이어가 "다음 라운드 확인" 버튼을 클릭합니다.
2. **검증 기준**:
   - 클릭 시 로컬 상태에서 임의로 화면이 전환되지 않고 그대로 대기하는지 확인합니다.
   - 모든 플레이어가 버튼을 누르면 서버로부터 `TURN_CHANGED`를 브로드캐스트 받아 일제히 다음 라운드의 **발언(SPEECH) 단계**로 정상 전환되는지 확인합니다.

---

## 2. 향후 검증 및 디버깅 필요 대상 (남은 문제점)

### [ ] 시나리오 3: 사망한 플레이어 투표 버튼 비활성화 검증 (확인 필요)
- **목표**: 이전 투표에서 사망한 플레이어(`status === 'DEAD'`)가 다음 라운드 투표 진입 시 투표 버튼이 원천적으로 비활성화되는지 확인합니다.
- **확인할 코드**: `App.jsx` 내 `VOTE_STARTED` / `VOTING_START`에서 사망 유저의 `canVote`가 `false`로 주입되는지와 `GameScreen.jsx` 내 버튼 비활성화 조건(`disabled={... || isDead}`)의 정상 작동 여부.

### [ ] 시나리오 4: 게임 시작 시 일부 플레이어 목록 누락 검증 (확인 필요)
- **목표**: 최초 게임 시작(`GAME_START` 수신) 시점 및 한 판이 완전히 끝나고 두 번째 게임을 시작할 때, 대기실의 일부 플레이어가 인게임 화면의 플레이어 리스트에서 누락되는 현상이 있는지 재현 경로를 추적합니다.

### [ ] 시나리오 5: 탈락 플레이어 새로고침 유실 검증 (확인 필요)
- **목표**: 인게임에서 탈락하여 사망(`DEAD`) 상태인 플레이어가 화면에 남아있어야 하는데, 새로고침 시 플레이어 목록에서 아예 사라지는 현상이 발생하는지 검증합니다.
- **확인할 코드**: `loadRoom()` 호출 결과로 전달받는 `players` 목록에 사망자가 포함되어 오는지(서버 응답 확인) 및 프론트에서 필터링 오류가 있는지 대조합니다.

### [ ] 시나리오 6: GAME_OVER 화면 새로고침 복원 검증 (별도 검증 예정)
- **목표**: 게임 종료(`GAME_OVER` 단계) 화면 노출 중에 새로고침(F5)을 했을 때 정상 복구되는지 여부를 검증하고, 미지원 시 추가 분석 및 구현 계획을 수립합니다.
