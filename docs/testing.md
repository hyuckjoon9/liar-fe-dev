# 테스트와 검증

이 문서는 라이어 게임 프론트엔드의 빌드 검증 방법과 수동 회귀 테스트(Manual Regression Testing) 시나리오 체크리스트를 정의한다. 백엔드 테스트 사양은 [liar-be-dev](https://hyuckjoon9.github.io/liar-be-dev) 및 읽기 전용 동기화 사본인 [testing.md](be_docs/testing.md)를 참조한다.

## 자동 빌드 검증

프론트엔드 프로젝트의 구문 오류, 의존성 모듈 링크, Vite 정적 번들링 이상 유무는 아래 명령어로 수행한다.

```powershell
npm run build
```

정상 실행 시 `dist/` 디렉터리에 빌드 산출물이 생성되며 에러 코드 없이 성공해야 한다.

---

## 수동 회귀 테스트 체크리스트

### 1. 방 생명주기 및 대기실 테스트

- [ ] **방 생성**: 방 생성 폼에서 닉네임, 공개/비공개(`visibility`), 최대 인원을 입력하고 방을 생성한다. 응답으로 받은 `roomCode`, `playerId`, `playerSecret`이 정상 저장되는지 확인한다.
- [ ] **닉네임 번호 부여**: 입력한 닉네임 뒤에 서버 부여 `#0000` 번호가 정상 표출되는지 확인한다.
- [ ] **방 목록 조회**: 공개방 생성 시 전체 방 목록(`RoomList.jsx`)에 방이 노출되고, 비공개방은 목록에 노출되지 않음을 확인한다.
- [ ] **방 설정 변경**: 대기실(`Lobby.jsx`)에서 방장이 카테고리(`FOOD`, `ANIMAL`, `PLACE`, `JOB`, `COUNTRY`, `RANDOM`) 및 시간 제한 프리셋(`FAST`, `STANDARD`, `RELAXED`)을 변경할 때 `PATCH /api/rooms/{roomCode}/settings`가 정상 전송되고 참가자 전원에게 갱신되는지 확인한다.
- [ ] **방장 위임 및 퇴장**: 방장이 퇴장할 경우 입장 순서가 빠른 남은 플레이어에게 방장 권한이 정상 위임되고 '게임 시작' 및 '게임 설정' 컨트롤이 활성화되는지 확인한다.

### 2. 게임 시작 및 역할 배정 테스트

- [ ] **최소 인원 조건**: 3인 미만 상태에서는 '게임 시작' 버튼이 비활성화되거나 거부되는지 확인한다.
- [ ] **인게임 화면 전환**: 3인 이상에서 방장이 게임 시작 클릭 시 인게임 화면(`GameScreen.jsx`)으로 전환되는지 확인한다.
- [ ] **역할/제시어 수신**: 시민은 제시어가 노출되고, 라이어는 제시어가 `null`("당신은 라이어입니다")로 표시되는지 확인한다.

### 3. 발언 단계 테스트

- [ ] **턴 활성화**: `currentTurnPlayerId`에 해당하는 플레이어의 입력창 및 '턴 넘기기' 버튼만 활성화되는지 확인한다.
- [ ] **발언 제출**: 발언 입력 후 전송 시 채팅 로그에 시간순으로 정상 표시되고 다음 턴으로 전이되는지 확인한다.
- [ ] **턴 넘기기**: '턴 넘기기' 버튼 클릭 시 `/pub/rooms/{roomCode}/skip`이 정상 전송되며 턴이 넘어가는지 확인한다.

### 4. 투표, 최후 변론 및 최종 판결 테스트

- [ ] **투표 대상 제한**: 본인 및 사망한 플레이어(`status === 'DEAD'`) 카드에는 투표 버튼이 비활성화되는지 확인한다.
- [ ] **최후 변론**: 단독 최다 득표자 발생 시 10초 최후 변론 타이머 화면이 표시되는지 확인한다.
- [ ] **최후 변론 발언**: 단독 최다 득표 후보자의 입력창만 활성화되고, 백엔드의 최후 변론 발언 허용 계약 반영 후 전송한 발언이 전체 채팅 로그에 표시되는지 확인한다.
- [ ] **최종 판결 (KILL / SAVE)**: 최후 변론 후 후보자 제외 생존자에게 `KILL` / `SAVE` 판결 버튼이 활성화되고 `/pub/game/final-vote`가 전송되는지 확인한다.
- [ ] **자동 다음 라운드 전환**: `VOTE_RESULT` 후 서버의 `TURN_CHANGED` 수신 시 확인 클릭 없이 발언 단계와 현재 턴이 표시되는지 확인한다.

### 5. 입력 및 로비 갱신 테스트

- [ ] **발언 글자 수**: 발언 입력창에 입력한 글자 수가 `현재 / 200`으로 갱신되는지 확인한다.
- [ ] **공개방 노출 지연**: 다른 브라우저의 메인 로비에서 공개방을 만들고 1초 이내에 목록에 나타나는지 확인한다.

### 6. 새로고침(F5) 복원 테스트

- [ ] **발언 단계 새로고침**: 발언 진행 중 F5 클릭 시 역할, 제시어, 발언 로그가 깨짐 없이 복원되는지 확인한다.
- [ ] **투표 결과 단계 새로고침**: `VOTE_RESULT` 화면에서 F5 클릭 시 이전 투표 결과 팝업이 정상 복구되는지 확인한다.
- [ ] **최후 단계 새로고침**: `FINAL_DEFENSE`·`FINAL_VOTE`에서 F5 클릭 시 후보자, 남은 게이지 시간, 최종 판결 제출·권한 상태가 서버 스냅샷과 일치하는지 확인한다.
- [ ] **게임 종료 새로고침**: 종료 뒤 방이 `WAITING` 상태여도 F5 클릭 시 `lastGameResult` 기반 게임 종료 모달이 표시되는지 확인한다.
- [ ] **사망자 표시 유지**: 새로고침 후에도 사망자(`DEAD`)가 플레이어 목록에서 삭제되지 않고 관전 상태 및 사망 아이콘이 유지되는지 확인한다.

### 7. 중복 접속 (세션 대체) 테스트

- [ ] **SESSION_REPLACED**: 동일 `playerId`로 다른 탭에서 접속 시 이전 탭에 세션 대체 안내 모달이 노출되고 이전 탭의 명령 송신이 차단되는지 확인한다.
