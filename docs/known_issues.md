# 알려진 문제점 (Known Issues)

본 문서는 실시간 게임 진행 중 발견된 프론트엔드/백엔드 동기화 관련 잔존 이슈들을 정리한 것입니다. 내일 디버깅 시 최우선적으로 해결해야 할 분석 대상 목록입니다.

---

## 1. 사망 플레이어의 투표 권한 미박탈 이슈 (확인 필요)
- **증상**: 투표 라운드 도중 사망 처리(`status === 'DEAD'`)된 플레이어임에도 불구하고 화면에 투표 버튼이 활성화되어 노출되는 경우가 존재합니다.
- **예상 원인**:
  - `App.jsx`에서 `VOTE_STARTED` 또는 `VOTING_START` 이벤트를 수신할 때 플레이어 생존 상태를 판별하는 `isDead` 로직이 `votePlayers` 배열에서 현재 사용자 ID를 정상 검색하지 못해 `canVote`가 잘못 `true`로 리셋될 수 있습니다.
  - `GameScreen.jsx` 내 `isDead` 또는 `voteState.canVote` 변수의 동기화 상태 및 버튼 `disabled` 조건 검사부의 누락 여부를 확인해야 합니다.

## 2. 플레이어 목록(Players List) 동기화 유실 이슈 (확인 필요)
- **증상**: 
  - 최초 게임 시작(`GAME_START` 수신) 직후 인게임 플레이어 카드 목록에 일부 참가자가 누락되는 현상이 발생합니다.
  - 한 게임이 완전히 종료된 후 두 번째 게임을 시작할 때도 일부 플레이어가 리스트에서 누락되어 발언 차례 등이 꼬이게 됩니다.
- **예상 원인**:
  - `App.jsx` 내 `GAME_START` 이벤트 처리 핸들러에서 방에 접속 중인 플레이어 목록(`data.players`)을 React State에 매핑하는 과정에서 상태 업데이트 충돌(Race Condition)이 발생하거나, 방장 시작 요청 이후 웹소켓 업데이트 패킷 누락이 의심됩니다.

## 3. 탈락 플레이어 새로고침 시 화면 유실 이슈 (확인 필요)
- **증상**: 탈락(`DEAD`)한 플레이어는 게임 화면 하단의 플레이어 리스트 영역에 탈락(💀) 레이블과 함께 남아있어야 하지만, 새로고침(F5)을 실행하면 해당 플레이어가 리스트에서 영구 소실되는 현상이 목격되었습니다.
- **예상 원인**:
  - 새로고침 시 복원을 위해 호출하는 `loadRoom()` REST API의 응답 데이터에서 탈락자 정보가 아예 누락되어 오거나, 정규화 헬퍼 함수 `normalizeRoom` 등에서 `status === 'DEAD'`인 유저들을 유실시키는 로직이 존재하는지 추적이 필요합니다.

## 4. GAME_OVER 화면의 새로고침 복원 구조 유실 (별도 검증 예정)
- **증상**: 게임이 종료된 상태(`GAME_OVER` 단계)에서 새로고침(F5)을 하면 결과 팝업창이 사라지거나 대기실 상태로 성급히 넘어가버리는 오동작이 우려됩니다.
- **예상 원인**:
  - `App.jsx` 내 `loadRoom` 복원 단계에서 `GAME_OVER` 페이즈에 해당하는 상태 정보 복원 코드가 현재 설계되어 있지 않습니다. 추후 복원 스펙 설계 및 검증이 필요합니다.
