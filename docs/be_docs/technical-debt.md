# 기술 부채와 후속 결정

현재 코드나 테스트에서 직접 확인되는 문제를 영향과 후속 판단 기준으로 정리한다. 완료된 변경은 [주요 변경 이력](change-history.md)에 기록한다.

## 운영 확장 전 결정

- 서버 재시작 후 복원이 필요하면 인메모리 `RoomManager`를 영속 저장 방식으로 대체한다.
- 다중 인스턴스 운영 전 프로세스 내부 잠금과 simple broker를 분산 동기화·메시징 방식으로 대체한다.
- 허용 origin과 credential 정책을 환경별 설정으로 분리한다.

## 남은 1차 MVP 후속 작업

### dev 배포

- Spring profile 기반 `local`·`dev` 설정과 Vercel dev origin CORS를 추가한다.
- 컨테이너 이미지를 만들고 GCP Cloud Run `dev`에 최소 인스턴스 0, 최대 인스턴스 1, WebSocket 요청 timeout 60분으로 배포한다.
- 배포 환경에서 REST, STOMP, 초대 링크, timeout과 입장 속도 제한을 수동 리허설한다.

### prod 전환 전 재검토

- 계정, 전적, 신고, 재시작 후 방·초대 링크 보존 중 하나가 필요해지면 PostgreSQL 도입과 Cloud SQL 비용·백업 요구를 함께 검토한다.
- 단일 인스턴스 제한을 풀기 전에 방·게임 상태와 메시지를 공유하는 저장소·브로커를 설계한다.
- 별도 `prod` 환경을 만들기 전에 비용 한도, 관측·알림, 배포·롤백 절차를 결정한다.
