# 주요 변경 이력

Git 커밋 전체를 반복하지 않고 사용자 관점에서 의미 있는 완료 변경만 기록한다. 현재 제약과 미완료 작업은 [기술 부채](technical-debt.md)를 참조한다.

## 2026-08-07 — 게임 타이머 세대 격리

- 이전 라운드나 단계의 만료 작업이 이후 라운드의 같은 플레이어 턴을 건너뛰지 않도록 모든 게임 예약 작업을 세대로 격리했다.
- 최후 변론 후보가 발언하면 발언 로그를 알린 직후 최종 판결 투표로 전환한다.

## 2026-08-06 — 최후 변론과 로비 실시간 목록

- 최후 변론 후보자의 발언을 채팅 로그에 표시하고, 로비 사용자가 공개방 목록을 실시간으로 구독할 수 있게 했다.

## 2026-08-06 — 표시 닉네임 번호 무작위화

- 방을 만들거나 입장할 때 표시 닉네임의 네 자리 번호를 무작위로 선택해, 서로 다른 닉네임이 모두 `#0000`으로 표시되던 문제를 해결했다.

## 2026-08-06 — 게임 상태 복원 계약 명확화

- 최종 판결의 절대 마감 시각과 일반 투표의 생존자·개인 후보 목록을 REST와 실시간 이벤트에서 명확한 필드명으로 제공해, 새로고침한 클라이언트도 남은 시간을 정확히 복원할 수 있게 했다.

## 2026-08-05 — MVP 게임 흐름 무결성

- 비공개방의 생명주기 변경을 전체 방 목록에 발행하지 않고, 새 방에 `RANDOM`·`STANDARD(30초/30초)` 설정을 적용하며 설정 변경을 대기 상태로 제한했다.
- 무투표 시간 만료도 결과를 알리고 다음 라운드로 진행하며, 라이어를 포함한 모든 단독 최다 득표 후보가 최후 변론과 최종 판결을 거쳐 `KILL` 과반일 때만 탈락하게 했다.
- REST 퇴장과 disconnect에서 떠난 플레이어의 최종 판결 표를 제거하고 현재 유권자로 완료 여부를 다시 계산하며, 최종 후보 퇴장도 기존 게임 종료 조건과 연계했다.

## 2026-08-05 — STOMP 연결 소유권

- 같은 플레이어가 새 탭에서 연결하면 새 STOMP session만 게임 명령을 보낼 수 있게 하고, 기존 탭에 이전 sessionId와 5초 종료 유예를 알린다.
- 새 탭의 상태 복원과 활성·대체 session disconnect 처리를 계약으로 문서화하고, 실제 두 STOMP session의 교체·투표 권한을 자동 검증한다.

## 2026-08-05 — REST 게임 스냅샷 격리

- 방 상세와 개인 게임 상태의 발언 순서·투표 결과를 방어 복사해, 응답을 만든 뒤 게임 상태가 바뀌어도 이미 반환한 REST 데이터가 변하지 않게 했다.

## 2026-08-05 — 시간 제한과 최종 판결 게임 흐름

- 발언·일반 투표에 시간 제한을 적용하고, 발언 시간 만료 또는 턴 넘기기에 미발언 기록을 남긴다.
- 단독 최다 득표자를 최후 변론과 `KILL`·`SAVE` 최종 판결로 진행하며, `KILL` 과반일 때만 탈락시킨다.
- 최종 판결 결과를 `VOTE_RESULT`로 알리고 후보·개인별 판결 가능 여부를 REST로 복원하며, 라이어 탈락은 `LIAR_FOUND`로 종료한다.

## 2026-08-05 — 공개·비공개 방과 초대 코드 입장

- 공개방만 목록에 노출하고, 비공개방은 6자리 초대 코드로 직접 입장할 수 있게 했다.
- 모든 참가자에게 서버 내 유일한 네 자리 번호를 붙이고 자동 방 제목을 만들며, 목록에 대기·게임중·정원 마감 상태를 제공한다.
- 존재하지 않는 초대 코드의 반복 요청을 IP별로 1분 10회로 제한하고 초과 시 429를 반환한다.

## 2026-08-01 — REST 상태 복원 일관성

- 방 상세와 개인 게임 상태 조회가 하나의 방 상태 시점을 기준으로 응답을 만들고, 마지막 플레이어 퇴장과 경합한 삭제된 방은 반환하지 않는다.

## 2026-08-01 — 입력 검증과 오류 응답 통일

- 방 설정의 카테고리와 제한시간을 검증하고, 잘못된 JSON과 처리되지 않은 서버 오류를 공통 API 오류 형식으로 반환한다.

## 2026-08-01 — 게임 핵심 흐름 자동 회귀 검증

- 투표 종료의 시민·라이어 승리, 게임 중 퇴장, 실제 STOMP 발언·투표, 동시 방 코드 충돌을 자동 테스트로 검증한다.

## 2026-07-31 — 방 코드 충돌 안전성

- 동시에 같은 방 코드가 선택돼도 기존 방을 덮어쓰지 않고 새 코드로 재시도한다.

## 2026-07-31 — 방 목록의 대기·게임중 표시

- 방 목록 REST와 실시간 목록 이벤트가 대기중과 게임중 방을 함께 제공한다.
- 게임 시작 시 목록 구독자에게 상태 변경을 알리고, `PLAYING`과 `VOTING`은 목록에서 모두 게임중으로 표시한다.

## 2026-07-31 — 투표 결과 뒤 자동 다음 라운드

- 시민 탈락 또는 동점 투표 결과를 4초간 보여준 뒤 다음 발언 라운드를 자동으로 시작한다.
- 수동 `next-round` STOMP 명령을 제거해 진행 권한과 중복 요청 문제를 없앴다.

## 2026-07-31 — 게임 종료 결과 복원

- 방 상세 REST가 마지막 게임의 승자·이유·라이어 정보를 다음 게임 시작 전까지 제공한다.

## 2026-07-31 — 동점 투표 처리

- 최다 득표 동점이면 아무도 탈락하지 않고 다음 라운드로 진행한다.
- REST와 WebSocket 투표 결과에 `tied`를 제공한다.

## 2026-07-31 — HTTP·STOMP 통합 테스트 추가

- `MockMvc`로 방 설정 변경과 퇴장의 HTTP 인증·오류 응답·상태 불변 계약을 검증한다.
- 실제 랜덤 포트와 STOMP 클라이언트로 `/ws` 연결, 개인 `ERROR` 이벤트, 잘못된 secret 요청의 상태 불변을 검증한다.

## 2026-07-31 — 상태 변경 요청 인증 확대

- 기존 `playerSecret` 검증을 방 설정 변경, 퇴장, 게임 시작, 발언, 투표, 다음 라운드까지 확대했다.
- REST 변경 요청은 `X-Player-Secret` header로, STOMP 명령은 `playerSecret` payload 필드로 본인 인증을 수행한다.

## 2026-07-26 — 프로젝트 문서 정비

- 문서를 아키텍처, 게임 흐름, REST, WebSocket, 테스트, 기술 부채, 변경 이력의 책임별 구조로 정리했다.
- 중복된 현재 작업 기록, 알려진 문제와 로드맵을 통합하고 일반 참고 링크 모음을 제거했다.
- 이후 문서 요청에서 같은 기준을 적용하도록 루트 `AGENTS.md`에 작성·검증 규칙을 추가했다.

## 2026-07-14 — REST 스냅샷과 동시성 제약 문서화

- 잠금 없는 REST 복원 조회와 방 코드 등록 경쟁 조건을 코드 기준으로 확인해 기록했다.
- 문서 진입점과 외부 계약의 책임을 분리했다.

## 2026-06-22 — 게임 상태 복원 보강

- 개인 game-state에 플레이어, phase, 턴, 투표와 발언 복원 정보를 추가했다.
- 사망한 플레이어를 전체 목록에 유지하고 투표 후보에서는 제외했다.
- 발언 당시 nickname과 전체 라운드 발언을 누적하도록 했다.
- `GAME_START`가 전체 플레이어 스냅샷을 제공하도록 했다.

## 2026-06-16 — 투표 결과 복원과 다음 라운드

- 시민 탈락 결과를 `VOTE_RESULT` 단계에서 REST로 복원할 수 있게 했다.
- 다음 라운드 명령이 투표 초기화와 생존자 발언 순서 재구성을 수행하도록 했다.

## 2026-06-15 — 개인 상태 조회 보호

- 방 생성·입장 시 `playerSecret`을 발급하고 개인 game-state 조회에서 검증하도록 했다.
- 공개 응답에서 secret, 역할, 제시어를 제외하고 라이어의 제시어를 `null`로 유지했다.
